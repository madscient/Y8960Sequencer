## 目的と範囲

Y8960 BASIC Extension の `MSAVE` が書き出すシーケンスデータ（`"Y8SQ"` ブロック、
`Y8960BasicExtension/doc/bytecode.md`）をファイルから読み、音源チップ
エミュレータで鳴らす**スタンドアローンのプレイヤー**。

- Windows / Linux / macOS
- コマンドラインと GUI
- **再生だけを提供する。** MML のコンパイル、BASIC との連携、MSX エミュレータ
  への組み込みは範囲外

## 決定事項

### 再生部は ROM の再生経路を C++ に移植する

ROM のシーケンサとデバイスドライバ（`Y8960BasicExtension/src/resident/seq*.asm`、
`src/dev/*.asm`、音律表と音色表）が各チップに書くレジスタの列を、C++ で再現して
エミュレータに渡す。

- 移植の元にした ROM の版を、移植したコードの側に記録する。ROM は開発中で、
  再生経路も動く
- **移植はコミット済みの版から読む**（`git show <commit>:<path>`）。ROM の作業ツリーは
  別のセッションが編集していて、未コミットの途中の状態を写すことがある
- シーケンサとドライバの移植は、`doc/rom-feedback.md` の A の修正が ROM に
  コミットされてから行う。それまでは ROM の中身に依らない部分（ブロックの読み込み、
  エミュレータの読み込み、音声出力と tick のタイミング、CLI）を作る

### ROM のコードと仕様が食い違うときは、仕様に合わせる

- 利用者の方針（2026-09-15）。ROM 側は不具合として直す
- 仕様が黙っている箇所と、スタンドアローンで足りない情報は、ROM 側へ返して仕様を
  調整する。返すものは `doc/rom-feedback.md` に溜め、結論が出るまでは同文書の
  「プレイヤーの暫定」で作る
- **前提**: 仕様文書（`bytecode.md` / `basic-reference.md`）が ROM の意図を表して
  いること。仕様だけでは決まらないものは同文書で ROM 側に問う

### ADPCM のサンプルは、シーケンスとは別のファイルで受け取る

- 利用者の方針（2026-09-15）。Y8960 の ADPCM は Y8950 と互換なので、adpcm_packer の
  `adpcm-b` の出力を使う
- ボイスファイル番号とサンプルの位置・速さを結び付ける情報（adpcm_packer の
  `.json` に当たるもの）は、**シーケンスデータのチャンクとして入る見込み**
  （利用者、2026-09-15）。チャンクの形は ROM 側で確定したら利用者から伝えられる
- **`--adpcm` が受け取るのは `Y8PC` 形式だけ**（利用者の決定、2026-09-17）。
  `CALL EXPORT PCM` が書き出す形で、仕様は ROM の `doc/pcmfile.md`。生のダンプは
  受け取らない
- ボイスファイルの設定は、ブロックのチャンク `03` にも入る。**両方あるときは
  `Y8PC` を優先する**（利用者の決定、2026-09-17）。`Y8PC` の設定は「全部置き換える」
  ものなので、混ぜない
- 結び付けが無いボイスファイルのキーオンは、ROM で `SET PCM` をしていないときと
  同じく何もしない

- 依存は CMake の FetchContent で取る

### エミュレータは、利用者が置いたビルド済みの共有ライブラリを実行時に読み込む

- 利用者の選択（2026-09-15）
- 使う3本と担当するブロック

| ライブラリ | チップ名 | Y8960 のブロック |
|---|---|---|
| Y8960emu | `OPLLEX` ×2、`OPL2EX` ×2 | OPLL-EX、OPL2-EX（ADPCM を含む） |
| EPSGemuEngine | `SSGS` | SSGS |
| DSAemuEngine | `DCSG` ×2、`SCC` | DCSG、SCC |

- 3本とも同じ名前の関数（`FmEngine_*`、`FmEngineApi.h`）を公開しているので、
  1つの実行ファイルに静的にリンクすると名前が衝突する。**実行時に読み込む
  方式はこの点でも必要**
- **実行ファイルと同じフォルダから探す**（利用者の決定、2026-09-15）。探す名前は
  各ライブラリの CMake が出力する名前

| ライブラリ | Windows | Linux | macOS |
|---|---|---|---|
| Y8960emu | `Y8960emuEngine.dll` | `libY8960emuEngine.so` | `libY8960emuEngine.dylib` |
| EPSGemuEngine | `EPSGemuEngine.dll` | `libEPSGemuEngine.so` | `libEPSGemuEngine.dylib` |
| DSAemuEngine | `DSAemuEngine.dll` | `libDSAemuEngine.so` | `libDSAemuEngine.dylib` |

- **前提**: 3本が FmEngineApi の C API を保ち、出力名を変えないこと。変わったら
  上の表と、名前を持つコード1箇所を直す

### コマンド名は `y8960player`、第1引数がシーケンスファイル、`--adpcm` で ADPCM

```
y8960player <シーケンスファイル> [--adpcm <ADPCM サンプルファイル>]
```

- 利用者の決定（2026-09-15）
- ほかの引数（tick の周期、繰り返し回数など）は、足すときにあらためて決める

### 入力ファイルは名前で選ばず、中身のヘッダで判断する

- 利用者の決定（2026-09-15）。拡張子などファイル名には制限を設けない
- 先頭の `"Y8SQ"` ヘッダ（`bytecode.md`「ブロック」）を見て受け付ける
- MSX の `BSAVE` で保存したファイルは先頭に 7 バイトの見出し（`FEh` で始まる）が
  付く。**付く場合と付かない場合があるので自動で判別する**（利用者の決定、
  2026-09-15）

### ライセンスは MIT、著者は madscient

- 利用者の決定（2026-09-15）。`LICENSE` に置いた
- **前提**: 音色データはシーケンスに埋め込まれていて、プレイヤーは ROM の音色表を
  持たない（利用者の理解、2026-09-15）
- ROM の `35cb6cb` で、OPL2EX のリズム音色（音色の索引 32-34）と ADPCM のボイス
  ファイルの控え（チャンク `03`）がブロックに入るようになった
- ROM の `b91892a` で、`@` を書かないトラックにも既定の音色のレコードが入るように
  なった。**これでブロックは音色について閉じ、プレイヤーは ROM の音色表を持たない**

## 見送った案

### ROM の Z80 コードをエミュレートして鳴らす

ROM イメージをそのまま Z80 エミュレータで走らせ、I/O ポートへの書き込みを
エミュレータに渡す案。ROM と同じ音になることが構造上保証される。

見送った理由:
- カートリッジのマッパー、RAM バンク、割り込み、MSX-TIMER を模す必要があり、
  MSX エミュレータの一部を作ることになる
- ROM イメージの配布が要る。ROM には他の拡張BASIC と、出典の違う音色データが
  含まれる
- 利用者から、MSX エミュレータへの統合は不要で、スタンドアローンの再生だけを
  提供すると示された

### エミュレータを submodule にしてこのリポジトリで一緒にビルドする

版を gitlink で固定でき、1回のビルドで揃う案。利用者が DLL を置く方式を選んだため
見送った。
