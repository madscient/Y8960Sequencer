## 目的と範囲

Y8960 BASIC Extension の `MSAVE` が書き出すシーケンスデータ（Y8SQ 形式の
`"Y8SQ"` ブロック、`Y8960BasicExtension/doc/bytecode.md`）をファイルから読み、音源チップ
エミュレータで鳴らす**スタンドアローンのプレイヤー**。鳴らすのは Y8SQ 形式のデバイス
0-11 ―― Y8960 の音源ブロック8つ（0-7）と、ROM が鳴らさない OPL3・OPM・OPNA・OPNB（8-11）。

- Windows / Linux / macOS
- コマンドラインと GUI
- **再生だけを提供する。** MML のコンパイル、BASIC との連携、MSX エミュレータ
  への組み込みは範囲外

## 決定事項

### 再生部は ROM の再生経路を C++ に移植する

ROM のシーケンサとデバイスドライバ（`Y8960BasicExtension/src/resident/seq*.asm`、
`src/dev/*.asm`、音律表と音色表）が各チップに書くレジスタの列を、C++ で再現して
エミュレータに渡す。

- 移植の元にした ROM の版を、移植したコードの側に記録する。ROM は開発中で、
  再生経路も動く
- **移植はコミット済みの版から読む**（`git show <commit>:<path>`）。ROM の作業ツリーは
  別のセッションが編集していて、未コミットの途中の状態を写すことがある
- シーケンサとドライバの移植は、`doc/rom-feedback.md` の A の修正が ROM に
  コミットされてから行う。それまでは ROM の中身に依らない部分（ブロックの読み込み、
  エミュレータの読み込み、音声出力と tick のタイミング、CLI）を作る

### ROM のコードと仕様が食い違うときは、仕様に合わせる

- 利用者の方針（2026-09-15）。ROM 側は不具合として直す
- 仕様が黙っている箇所と、スタンドアローンで足りない情報は、ROM 側へ返して仕様を
  調整する。返すものは `doc/rom-feedback.md` に溜め、結論が出るまでは同文書の
  「プレイヤーの暫定」で作る
- **前提**: 仕様文書（`bytecode.md` / `basic-reference.md`）が ROM の意図を表して
  いること。仕様だけでは決まらないものは同文書で ROM 側に問う

### ADPCM のサンプルは、シーケンスとは別のファイルで受け取る

- 利用者の方針（2026-09-15）。Y8960 の ADPCM は Y8950 と互換なので、adpcm_packer の
  `adpcm-b` の出力を使う
- ボイスファイル番号とサンプルの位置・速さを結び付ける情報（adpcm_packer の
  `.json` に当たるもの）は、**シーケンスデータのチャンクとして入る見込み**
  （利用者、2026-09-15）。チャンクの形は ROM 側で確定したら利用者から伝えられる
- **`--adpcm` が受け取るのは `Y8PC` 形式だけ**（利用者の決定、2026-09-17）。
  `CALL EXPORT PCM` が書き出す形で、仕様は ROM の `doc/pcmfile.md`。生のダンプは
  受け取らない
- ボイスファイルの設定は、ブロックのチャンク `03` にも入る。**両方あるときは
  `Y8PC` を優先する**（利用者の決定、2026-09-17）。`Y8PC` の設定は「全部置き換える」
  ものなので、混ぜない
- 結び付けが無いボイスファイルのキーオンは、ROM で `SET PCM` をしていないときと
  同じく何もしない

### エミュレータは、利用者が置いたビルド済みの共有ライブラリを実行時に読み込む

- 利用者の選択（2026-09-15）。YMEngine は利用者の指示（2026-10-01、デバイス 8-11 を鳴らす）
- 使う4本と担当するデバイス

| ライブラリ | チップ名 | デバイス |
|---|---|---|
| Y8960emu | `OPLLEX` ×2、`OPL2EX` ×2 | OPLL-EX、OPL2-EX（ADPCM を含む） |
| EPSGemuEngine | `SSGS` | SSGS |
| DSAemuEngine | `DCSG` ×2、`SCC` | DCSG、SCC |
| YMEngine | `OPL3`、`OPM`、`OPNA`、`OPNBB` | OPL3、OPM、OPNA、OPNB（下の「デバイス 8-11」） |

- 4本とも同じ名前の関数（`FmEngine_*`、`FmEngineApi.h`）を公開しているので、
  1つの実行ファイルに静的にリンクすると名前が衝突する。**実行時に読み込む
  方式はこの点でも必要**
- **実行ファイルと同じフォルダから探す**（利用者の決定、2026-09-15）。探す名前は
  各ライブラリの CMake が出力する名前

| ライブラリ | Windows | Linux | macOS |
|---|---|---|---|
| Y8960emu | `Y8960emuEngine.dll` | `libY8960emuEngine.so` | `libY8960emuEngine.dylib` |
| EPSGemuEngine | `EPSGemuEngine.dll` | `libEPSGemuEngine.so` | `libEPSGemuEngine.dylib` |
| DSAemuEngine | `DSAemuEngine.dll` | `libDSAemuEngine.so` | `libDSAemuEngine.dylib` |
| YMEngine | `YMFMEngine.dll` | `libYMFMEngine.so` | `libYMFMEngine.dylib` |

- **前提**: 4本が FmEngineApi の C API を保ち、出力名を変えないこと。変わったら
  上の表と、名前を持つコード1箇所を直す
- **YMEngine も必須にした**（こちらで決めた、2026-10-01）。無ければデバイス 0-7 だけの曲も
  開けない。無いときにデバイス 8-11 だけを「鳴らさないデバイス」として飛ばす形もありうるが、
  `Y8960Chips` が欠けたエンジンを持つ分岐が要る。配布物には同梱するので、要らないと判断した。
  値段: `chips.cpp` の `open` と `render` に分岐、試験の登録条件

### コマンド名は `y8960player`、第1引数がシーケンスファイル、`--adpcm` で ADPCM

```
y8960player <シーケンスファイル> [--adpcm <ADPCM サンプルファイル>] [--tick <0-2>]
            [--repeat <0-255>] [--mute <指定>]... [--wav <出力ファイル>]
```

- 利用者の決定（2026-09-15、`--tick` は 2026-09-18、`--mute` `--wav` `--repeat` は 2026-09-19）
- **`--tick` の値の意味は `CALL MINIT` の分解能と同じ。** 0 が約60Hz、1 が約100Hz、
  2 が約200Hz、省略時は 2。ROM に無い 50Hz は CLI からは選べない（GUI にはある）
- **`--mixer` は保留。** デバイスごとの音量を `MIXER` と同じ意味で指定したいが、
  ROM の `MIXER` 文がまだ実装されておらず、実機のデジタルミキサーのレジスタ仕様も
  決まっていない（利用者、2026-09-18）。値の口だけは `Y8960Chips::setGain` に
  用意してあり、`tests/render_test.cpp` が効くことを見ている
- **`--repeat` の値の意味は `CALL MSTART` のリピート回数と同じ**（0-255、0 は無限、
  省略時 1）。利用者の指示（2026-09-19）が `--repeat 0` と書いていたので、それに
  合わせて足した

### コンソールと画面に出す文字列は英語で、ASCII に収める

- 利用者の決定（2026-09-19）。CLI のメッセージ、コアのエラー文（CLI と GUI の両方に
  出る）、GUI の文字が対象。コメントは日本語のまま
- **`tools/check_ascii_strings.py` が `src/` の文字列リテラルを検査し、ctest の
  `ascii_strings` として走る。** 非 ASCII の文字列リテラルがあれば場所を出して落ちる
- 利用者が渡したファイル名はそのまま表示するので、そこには非 ASCII が出うる。
  Windows でそれが化けないよう、CLI はコンソールの出力を UTF-8 にしている

### WAV の書き出し（CLI の `--wav`）

- 利用者の指示（2026-09-19）。**`--repeat 0` と一緒に指定したらエラー**（利用者の決定）
- **書き出しの形はこちらで決めた**：48000Hz・16bit・ステレオの PCM。再生と同じ
  サンプリング周波数。変えるなら `src/cli/main.cpp` の定数と `WavWriter` だけ
- 音声デバイスは開かず、鳴らさない（`PlaybackEngine::open` の `withAudio`）
- **曲が終わったあとの余韻**：音が 0.5 秒続けて消えるまで、最長 5 秒書く。
  **16bit の 1 LSB までは無音とみなす** ―― DSAemuEngine（`0f5c786`）の SCC は、
  キーオフのあとも 1 LSB ほどの一定値を出し続けていて（測った）、厳密な 0 を
  待つと毎回 5 秒まで伸びた
- 終わらない曲の保険として 30 分で打ち切り、その旨を出す。`!` の組み合わせや
  ダルセーニョで、`--repeat` が 1 でも終わらない曲はありうる

### ミュート（CLI の `--mute`、GUI のチップ・チャンネル単位）

- 利用者の決定（2026-09-19）。書式は
  `--mute {<チップシンボル>[,<CH番号>]|T<トラック番号>|<トラックシンボルA-P>}`、
  頭の `!` で「それ以外」、複数指定可、使われていないものの指定は受け付けて何もしない
- **チップシンボルはこちらで決めた**：`SSGS` `OPLLEX1` `OPLLEX2` `OPL2EX1` `OPL2EX2`
  `DCSG1` `DCSG2` `SCC`、デバイス 8-11 は `OPL3` `OPM` `OPNA` `OPNB`（2026-10-01）。
  `bytecode.md` のデバイス表の名前から空白を除いたもの
  （ROM の `naming.md` はチップの名前を持たない）。**変えるなら `src/core/mute.cpp`
  の表1つと README の表**
- 大文字と小文字は区別しない。CH 番号はシーケンスデータのチャンネル番号と同じ
- **`!` の付いた指定と付かない指定が混ざったとき**：`!` の付いた指定の和集合に
  入らないトラックを黙らせ、そのうえで `!` の無い指定を黙らせる。**利用者の指定に
  この場合の規則は無く、こちらで決めた**
- 形は合っていてもチップが持たないチャンネル（`SCC,7` など）は、打ち間違いとして
  拒む。使われていないだけのもの（`DCSG2` を使わない曲の `DCSG2`）は受け付ける
- **どの指定もトラックに解決する。** 1チャンネルを持つのは1トラックだけなので、
  チャンネルはそれを持つトラック、チップはそのチップのトラック全部になる
- トラックのミュートは ROM の `MMUTE`（シーケンス単位）と同じ動き ―― キーオンと
  リズムの打撃を止め、音量は 0 を書く。鳴っている音はキーオフしない
- GUI ではリズムチャンネルを1本として黙らせる（楽器ごとには分けない）。CLI の
  チャンネル指定と揃えるため

### GUI のレベルメーターは、ブロックごと・チャンネルごとに分ける

- 利用者の決定（2026-09-18）。見た目は `../FITOM_X` の `LevelMeterPanel` に合わせる
  ―― LED のセグメントを積んだバー、下が緑・上が黄と赤、消えているセグメントも
  暗い色、ピークホールド、バーの下にラベル。ブロックを1つの帯として縦に積む
- **エミュレータから取れるのはチップ単位の音だけなので、チャンネルごとの値は
  FITOM_X と同じくキーオンとそのときの音量から作る。** シーケンサが
  `ChannelActivity`（`src/core/activity.h`）に書き、画面が読む。落ち方は画面が作る
- リズムチャンネルは楽器ごとに分ける。OPLLEX・OPL2EX・OPL3 は5つ（BD・SD・TM・CY・HH）、
  OPNA と OPNB は6つ。`V` と `@A` のどちらが効いたかは、そのときのアクセントのビットで決まる
- 既定では、読み込んだシーケンスが使うチャンネルだけを出す。`All channels` を
  立てると全デバイスの全チャンネルを出す
- ブロックごとの音量（`--mixer`）のために、**音源ブロックごとにエンジンを1つ持つ
  形に変えた**（前は3本のライブラリに1つずつ）。こちらは実際の出力の最大振幅を
  持つので、ブロック単位のレベルは音そのものから取れる
- **前提**: ブロックごとに別のエンジンを持っても、合成した音は1つのエンジンに
  まとめたときと変わらない。エンジンはチップごとに生成して足しているため

### Windows 版の配布物は、エミュレータを同梱した zip

利用者の決定（2026-09-19、v0.1.0）。`tools/package_windows.py` が作る。

- 4つのエミュレータの DLL を同梱し、`licenses/` に同梱物すべてのライセンス文を
  入れる（エミュレータ4つ、ymfm、MAME 由来の3つ、emu* の5つ、SDL3、Dear ImGui）。
  ymfm は Y8960emu と YMEngine の両方が持つが、ライセンス文は同じなので1つ（Y8960emu のもの）。
  **ライセンス文が揃っていなければ、ビルドの前に止まる**
  どれも表示を条件に再頒布を許すライセンス。エミュレータの `extern/` が増えたら、
  スクリプトの一覧も足す
- CRT を静的リンクする（`CMAKE_MSVC_RUNTIME_LIBRARY=MultiThreaded`）。VC++ の
  再頒布パッケージを利用者に入れさせないため。モジュールごとに CRT のヒープが
  別になるが、FmEngineApi は C の関数だけで、確保と解放がモジュールをまたがない
  ので成り立つ。**API がモジュールをまたいでメモリを渡すようになったら成り立たない**
- `subst` で割り当てたドライブの上でビルドする。SDL3 の `__FILE__` が実行ファイルに
  残り、実際のパスには利用者の名前が入るため。スクリプトは仕上がったバイナリを
  ホームフォルダのパスで検査し、見つかれば zip を作らない
- Linux と macOS の配布物は作らない（ソースからビルドする）

### デバイス 8-11（OPL3・OPM・OPNA・OPNB）は YMEngine で鳴らす

利用者の指示（2026-10-01）「対応チップが増えたので、`../YMEngine` を使って演奏できるように」。
形式は ROM の `1b06823`・`e6f5bf0`・`8fa6de3` の `bytecode.md`。ROM はこれらを鳴らさない
（読み飛ばす）ので、**ドライバに写し元は無く、`bytecode.md` の定めとチップのレジスタから作った。**
レジスタの置き場所とビットは、記憶ではなく YMEngine が使う ymfm（`81aec25`）のソースで確かめた。

- **OPNB は YM2610B（YMEngine の `OPNBB`）として作る**（こちらで決めた）。形式は OPNB と
  OPNB-B を区別せず、FM を6チャンネル持つのは OPNB-B。YM2610 のシーケンスはチャンネル 0 と 3 を
  使わないので、B で鳴らしても同じ。値段: `chips.cpp` の表の1語
- **クロックは各チップの標準**（OPL3 14.31818MHz、OPM 3.579545MHz、OPNA 7.9872MHz、
  OPNB 8MHz。こちらで決めた）。形式はクロックを決めていない。音の高さの計算も同じ値を使う。
  値段: `pitch.h` の定数4つと README の1行。**前提**: 形式がクロックを決めないこと
- **音の高さは平均律（O4 A が 440Hz）から浮動小数で出す。** ROM の音律表に当たるものが
  無いため。OPN 系は F-Number が 11 ビットに収まるいちばん小さいブロック、OPM は KC と KF
  （KF の 1/64 半音はベンドの歩みと同じ）、OPL3 は OPL2 と同じ F-Number（`oplPitch`）。
  OPN 系の SSG の分周値はマスタークロック ÷ 64 ÷ 周波数（ymfm の SSG の刻みから）
- **FM の音量**：キャリアの TL に `(127 − 音量) ÷ 2` を足す。OPL2EX と同じ量（こちらで
  決めた。形式は「読み替えはドライバの仕事」とだけ言う）。OPL2EX と違い、**アルゴリズムで
  出力に出るオペレータすべて**に足す。値段: 各ドライバの `writeLevels` 1つずつ
- **ADPCM-B は、OPL2EX と同じ ADPCM メモリ（`--adpcm` の `Y8PC`）を鳴らす。** 根拠は
  `bytecode.md` の「ボイスファイル番号はデバイスを区別しない」。アドレスの単位は OPNA が
  8 ビット単位の DRAM（32 バイト、ctrl2 の bit1 を立てる）、OPNB が 256 バイト
- **OPNA のリズムと OPNB の ADPCM-A は鳴らさない**（こちらで決めた）。サンプルの中身
  （OPNA はチップ内蔵の ROM、OPNB はサンプル ROM）を渡す手段が無く、中身が無いと ymfm は
  0 のバイト列を復号して大きな雑音を出す（**確認済み**：6楽器を叩いて RMS 1.02。FM の音は
  0.01 前後）。ドライバはレジスタを書き、`Y8960Chips::write` が ADPCM-A のキーオンだけを
  捨てる。**前提**: 中身を渡す手段が無いこと。手段を足したら、その1行を条件付きにする
- **OPL3 の 4OP の組は、前側のキーを後ろ側にも揃えて書く。** ymfm は 104h の変化を次の
  クロックでオペレータの割り当てに反映するので、`85` で 104h を立てた同じ tick に前側だけを
  キーオンすると OP3・OP4 がキーオンされず、FM-FM では無音になった（**確認済み**、下の進捗）。
  実機は 4OP の後ろ側のキーを見ない（**推測**：YMF262 の 4OP の説明から。実機では見ていない）。
  **前提**: ymfm がこの遅れを持つこと。直れば後ろ側を書かなくてよいが、書いても害は無い
- **形式が言わない初期値**（こちらで決めた）：OPL3 は出力 A・B を入れ、C・D は切る。OPM・
  OPN 系・OPL3 の定位は両方。LFO・タイマーは 0。OPNA のリズムと OPNB の ADPCM-A の全体の
  音量は最大。「演奏を始める前の初期化はシーケンスの外」（`bytecode.md`）の、その外にあたる
- **`E9` は、FX の無い音色のあいだは捨てる。** 「FX が 0 の音色では、読み手は `E9` を無視する」
  をそのまま読んだ。`85` より前に来た `E9` も捨てることになる（`doc/rom-feedback.md` の C4）
- **チャンク `41` は、デバイス 11 のものだけを持つ。** 8-10 のものは鳴るものを変えないので
  受け取って捨て、0-7 のものは ROM の読み手と同じく拒む（こちらで決めた。形式は `41` の
  デバイス番号の範囲を言わない）
- **デバイス 12 以上のトラックは、警告を出して割り当てない。** 形式の「鳴らさないデバイスは
  読み飛ばしてよい」に当てはめた。ROM も同じ扱い（`8fa6de3`）
- **ミュートのチップシンボルは `OPL3` `OPM` `OPNA` `OPNB`**（こちらで決めた）。`bytecode.md` の
  デバイス表の名前そのまま。値段: `src/core/mute.cpp` の表と README の表
- レベルメーターの名前（こちらで決めた）：OPL3 の 4OP は `Q1`-`Q6`、OPN 系の SSG は `SA`-`SC`、
  OPNA のリズムは `BD SD CY HH TM RM`、OPNB の ADPCM-A は `A1`-`A6`、ADPCM-B は `PCM`

### Y8SQ 形式の拡張で、デバイス 0-7 の読み方も変わった

ROM の `f35b7e7`（`B3`）、`1b06823`（チャンク `01` と `82`）、`e6f5bf0`・`8fa6de3`（`87`）。

- **チャンク `01` は 12 バイトのレジスタイメージ。** OPLLEX と OPL2EX で共用し、長さが違えば
  ブロックごと拒む（形式どおり）。前の 32 バイトの形（BASIC 形式）は読まない ―― 下の「見送った案」
- **OPLLEX も音色の移調を足す**（ROM が `1b06823` で直した）。`82`（チップのプリセット）では 0
- **`82` は、OPLLEX ではバンク（bit5-4）とプリセット（bit3-0）で bit7-6 を見ない。** OPL2EX の
  FM と SCC では引数によらず捨てる（こちらはもともと捨てていた）
- **SSGS の定位は `87`。** `B1` は形式から消えたので何もしない
- **SCC の `B3`**：0 は音量を表を通さずに書く。周の頭で表に戻す（ドライバの `rewindChannel`）
- `E8`（2組目への書き込み）は、2組目を持たないデバイスでは捨てる

## 見送った案

### 前の形のチャンク `01`（32 バイトの BASIC 形式）も読む

見送った（2026-10-01）。理由：形式が長さの違うものを拒むと定めていて、ROM も互換を捨てた
（ROM の段階28「BASIC 形式を残す理由が後方互換だけで、実物がまだ無いので捨ててよい」）。
方針「ROM のコードと仕様が食い違うときは、仕様に合わせる」にも沿う。引き換えに、前の形で
書き出された `.SQ`（手元では `Y8960SeqConverter/dist/chk/L.SQ`）は読めない。長さで見分けられる
ので、読むことにしても `block.cpp` に変換を1つ足すだけで済む

### ROM の Z80 コードをエミュレートして鳴らす

ROM イメージをそのまま Z80 エミュレータで走らせ、I/O ポートへの書き込みを
エミュレータに渡す案。ROM と同じ音になることが構造上保証される。

見送った理由:
- カートリッジのマッパー、RAM バンク、割り込み、MSX-TIMER を模す必要があり、
  MSX エミュレータの一部を作ることになる
- ROM イメージの配布が要る。ROM には他の拡張BASIC と、出典の違う音色データが
  含まれる
- 利用者から、MSX エミュレータへの統合は不要で、スタンドアローンの再生だけを
  提供すると示された

### エミュレータを submodule にしてこのリポジトリで一緒にビルドする

版を gitlink で固定でき、1回のビルドで揃う案。利用者が DLL を置く方式を選んだため
見送った。

### Debian 11（WSL2）で窓と音声出力を確かめる

見送った。理由：その環境には SDL3 が求める開発用パッケージをもう入れられない
（利用者の判断、2026-09-19）。ビルド・試験・WAV の書き出しはその環境で確かめてある。
パッケージを入れられる Linux が用意できれば、この判断は要らなくなる。
