# Y8960 BASIC Extension へのフィードバック

**この文書は、プレイヤーを作る側から Y8960 BASIC Extension（以下 ROM）へ返す
情報の一覧。** 中身は3種類。

- ROM の再生経路のコードが仕様（`bytecode.md` / `basic-reference.md`）と
  食い違っている箇所
- 仕様が黙っていて、意図の確認が要る箇所
- スタンドアローンのプレイヤーが、ブロックだけでは ROM と同じ音を出せない理由

読者と前提。

- 読者: ROM の開発者、ROM とプレイヤーを編集する AI
- 最初にまとめたのは ROM の `0b752a5`。**いまの内容は `d2e64a3` で見直したもの。
  挙げた食い違いと確認事項はすべて片付いている**
- ファイル名は、断りが無ければ `Y8960BasicExtension/` からの相対
- **どの項目も、コードを読んで追っただけで、実行はしていない。** チップの一般的な
  振る舞いなどから考えた箇所は「推測」と書く

## 扱いの方針

- **食い違いは仕様に合わせる。** ROM 側は不具合として直す。プレイヤーは最初から
  仕様どおりに作る
- **仕様が黙っているものは ROM 側で仕様を調整する。** 結論が出るまで、プレイヤーは
  各項目の「プレイヤーの暫定」で作る
- 新しく見つけたものはこの文書に足す。ROM 側のセッションへ渡すのは利用者で、
  プレイヤーの作業から ROM のリポジトリへは書き込まない

## A. ROM で直ったもの

`35cb6cb`「再生経路の食い違いを直し、OPLLEX の音色番号とブロックの中身を仕様に
揃える」ほかで直った。**プレイヤーは仕様どおりに作ればよい。**

| 直った食い違い | プレイヤーが従う形 |
|---|---|
| ポルタメントの歩幅が溢れて目標に届かない | 歩幅を 24 ビットで持ち、音符の終わりに到達する |
| SCC の `85` がレジスタの残り値しだいで抜ける | 索引で「もう載っているか」を判定する |
| ダカーポ・フィーネの tick に上位のトラックが進む | 発火した tick の残りのトラックは処理しない |
| 周の境目で 1 tick 伸びる | 巻き戻した tick のうちに次の周の先頭を読む。**時間を取らない周だけは次の tick を待つ** |
| 長さ 0 のイベントが 1 tick を取る | 同じ tick のうちに次のイベントへ進む |
| フェード中に 1 割り込みの tick 数が減る | フェードの有無で tick の進み方を変えない |
| リズムモードで ch6-8 の F-Number が 0 のまま | リズムモードに入るとき ch6-8 に F-Number を書く（MMBE と MABEL の値） |
| リズムにシーケンス音量・ミュート・フェードが効かない | リズムの `V` と `@A` にも掛ける |
| リズムのアクセントがコンパイル順の差分で出る | **`A8` は次の `A8` まで効く**（`bytecode.md`）。コンパイラが到達点ごとに `A8` を出す |
| `Y` の書き込みがドライバの控えに入らない | `Y` の書き込みをドライバの控えにも入れる |
| OPL2EX の `@n` が表のレコードではなく作業領域を読む | ―― |
| リズムモードが `MINIT` の引数（`252cf1d`） | **シーケンスが演奏開始時に決める。** ch10 を持つ FM ブロックは入り、ch6-8 を持つブロックは出る |
| OPL2EX のリズム音色とブロックの閉じ方 | ブロックが索引 32-34 に持つ（`bytecode.md`「ブロック」） |
| ADPCM のボイスファイルの置き場所が分からない | ブロックのチャンク `03` が持つ。ファイルの形は `pcmfile.md` |

**プレイヤー側の反映**（2026-09-16）

- ブロックの読み込みが、チャンク `03` と索引 32-34 を読むようになった
- リズムモードの推定（ch10 があれば入る）は、そのまま ROM の決め方と一致する

## B. 2回目の見直しで直ったもの

`b91892a`「`@n` の無いトラックにも既定の音色のレコードを持たせる」と
`d2e64a3`「仕様が名前を付けていなかった4つの隅を、実装に合わせて書く」で片付いた。
**残っている項目は無い。**

| 項目 | 仕様がいまどう書いているか | プレイヤーが従う形 |
|---|---|---|
| `@` を書かないトラックの音色 | 書き手は最初のキーオンの前に `85` を出し、既定の音色 0 のレコードをブロックに入れる。読み手は音色表を持たなくてよい | 番号で音色表を引く経路は持たない。`85` のレコードだけを読む |
| クオンタイズ 0 | 範囲は **1-8**。`83 00` を書いたブロックの鳴り方は決まっていない | `GATE = max(1, 長さ × Q ÷ 8)`。短い音符でゲートが 0 になるときの 1 tick への切り上げは仕様どおり |
| 到達カウンタの一周 | 1バイトで **256 回で一周**する。発火した回数のトゥコーダは 256 回ごとにまた発火し、発火回数 0 は 256 回目の到達で発火する | 同じく 1 バイトで回す（**以前の暫定「255 で止める」は取り消し**） |
| 時間を取らないイベントの打ち切り | **256 個**続いたら読み手はそのトラックを終わらせる。数えるのはイベント1つごとで、時間を取るイベントで数え直す | 同じにする |
| チャンク `03` の検査 | **ROM は中身を検査しない。** 値が壊れていてもブロックは拒まれない。値を使う読み手が自分で検査する。範囲は `pcmfile.md` の設定1件と同じ | 使う側なので検査する。**壊れた項目だけを捨てて警告し、ブロックは読む** |
## C. ブロックの外にあり、プレイヤーが外から与えるもの

ROM の欠陥ではない。ブロック1つを渡しただけでは ROM と同じ音にならない理由の一覧。

| 項目 | ROM での決まり方 | プレイヤーの扱い |
|---|---|---|
| tick の割り込み周期 | `MINIT` / `SQINIT` の引数（60・50・100・200Hz） | 利用者が選ぶ。既定は 200Hz |
| 繰り返し回数 | `MSTART` の引数 | 利用者が選ぶ |
| 全体の音程のずらし | `MTUNE` | 0（440.0Hz） |
| ADPCM のサンプル | `SET PCM` / `IMPORT PCM`。置き場所と周波数はブロックのチャンク `03` にもある | `--adpcm` の `Y8PC` ファイル。設定を持っていればチャンク `03` より優先し、持っていなければチャンク `03` を使う |
| 開始時のテンポ | 120 に固定。周ごとにも 120 に戻る。**`bytecode.md` の走行状態の表に無い** | 同じにする |
| リズムモード | **解決済み。** シーケンスが演奏開始時に決める（`252cf1d`） | ブロックの割り当てから同じに決める |
